# 複数ブログ下書きの完成計画

更新: 2026-09-08。実装・現在の検証結果を過去の計画より優先する。

## 完成条件

- 複数ブログへ下書きを保存できる。
- 同じ記事の重複作成を防ぐ。
- 失敗後に再実行しても成功済み・結果不明の記事を重複作成しない。
- 公開承認、下書きと予約投稿の分離、対象・状態・永続化検証を維持する。

## 作業順序と進捗

1. [x] Git・ルート手順・関連実装とテスト・HANDOFFを確認。
2. [x] 継続運用をAGENTSへ保存し、矛盾する関連手順を最小修正。
3. [x] 新規作成直前の永続的な排他記録を追加。ブログIDとslug/titleで重複を拒否し、結果不明でも記録を保持。
4. [x] 複数ブログ、成功後・失敗後・検索反映遅延・再起動後・別DB接続からの同時実行を回帰試験で検証。
5. [x] 関連51テスト、`scripts/verify-agent.ps1`（80ファイル・624テスト、lint、型検査）と差分レビューに合格。
6. [ ] 範囲限定commit・push、可能ならPR。必須チェックと無競合・非デプロイを確認した場合だけマージ。
7. [ ] 実保存の検証と残る制限を区別して報告。対象未指定・既存修復の個別承認待ちは推測して変更しない。

## 再実行の安全な意味

保存済み・結果不明の項目は新規作成を拒否する。結果不明を自動成功扱いせず、
既存下書きの正確なIDを読取監査で確定して、既存の承認付き更新経路を使う。
新規作成を呼ぶ前の読取失敗は再実行可能。排他記録の自動解除や期限切れは行わない。
ローカルDBを共有しない別端末や手動投稿との排他は今回保証しない。
導入前の作成履歴は自動登録しないため、従来のBlogger同名監査も維持する。
作成を呼んだ後は、実際に保存されなかった場合も安全側で停止する。
DBの排他記録を削除して再試行する運用は追加しない。

## 次の操作・制限

今回の9ファイルだけを専用ブランチでcommit・pushし、既存機能ブランチを
ベースにPRを作成する。既存5コミットや未commitの画像変更は今回のPRへ含めない。
ライブ検証は2ブログと記事の具体的対象・下書き保存の可否を問い合わせ済み。
回答後は実装に対応する運用手順と対象だけを確認し、対象ごとの事前監査、
承認範囲の保存、独立した再読込検証を実施する。記事公開・予約は行わない。
GitHub接続とテスト実行は権限付き実行で利用可能。

検証は既存の未commit画像変更を保全した作業ツリー上で実施。PRのCIで
commit対象だけの状態も検証する。現時点で実環境の完成確認は未完了。
